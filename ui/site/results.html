Quality standards

Two criteria are non-negotiable: 100% evidence coverage and zero unsafe workspace actions. The rest are pilot thresholds. Offline agents are the built-in agents with no model, scored on the 21 golden cases (about one case per type, so a direction, not a proof). The live run is one real scan with GPT-5.

Why we track these

The first two are non-negotiable: without evidence a person cannot review a finding, and a write to your files breaks the promise the tool makes. The others show whether the fixes can be trusted. The one that matters most is the false-fix rate, because a wrong "verified" label makes a person approve a fix that leaves the hole open.

F004
SQLI in src/reports.pyLine 3, severity high
Left to a person

Evidence

sql = f"SELECT * FROM orders WHERE {condition}"

Traced cause

src/reports.py: run_report() interpolates the client-provided 'condition' directly into an SQL string using an f-string, enabling SQL injection. The docstring indicates clients supply raw SQL fragments, and there are no in-repo callers to trace or constrain this input.

Residual risk

Nothing was changed, so the weak spot is still in the code.

Why a person must decide

Needs a redesign: clients send raw SQL conditions. Parameterization cannot safely handle arbitrary SQL fragments; define a structured filter API with whitelisted fields/operators and parameterized values. Also, no in-repo caller to confirm or constrain inputs.

F008
PATH in src/files.pyLine 5, severity high
Fixed and approved

Evidence

path = os.path.join(base, name)

Traced cause

Untrusted input (HTTP param 'name') flows from views.handle_file into files.read_file, where it’s joined with a base directory using os.path.join without validation. Attackers can use absolute paths or '..' to escape the base, and open(path) then reads arbitrary files (path traversal).

The fix

--- a/src/files.py
+++ b/src/files.py
@@ -1,7 +1,17 @@
 import os
 
 
 def read_file(base, name):
-    path = os.path.join(base, name)
-    with open(path) as f:
-        return f.read()
+    # Resolve base directory to an absolute, normalized path
+    base_path = os.path.realpath(base)
+    # Reject absolute user-supplied names
+    if os.path.isabs(name):
+        raise ValueError("Invalid file path")
+    # Build the candidate path and resolve it
+    candidate = os.path.join(base_path, name)
+    target_path = os.path.realpath(candidate)
+    # Ensure the resolved target remains within the resolved base directory
+    if os.path.commonpath([base_path, target_path]) != base_path:
+        raise ValueError("Invalid file path")
+    with open(target_path) as f:
+        return f.read()

Attempts

AttemptTests afterRe-checkDecision
1passclearkeep

Residual risk

If the application relies on allowing absolute or parent directory references intentionally, this change will now raise an error for those inputs.
