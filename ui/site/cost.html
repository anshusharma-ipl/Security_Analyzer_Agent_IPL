The scan stopped at the old 60-call cap after 6 of 10 findings (5 fixes verified, 1 for a person, 4 not reached). Per finding that is about 24,800 input and 4,700 output tokens. The characters-divided-by-four proxy predicted about 18,300 input and 2,400 output for the same 6 findings, so the real input was about 8 times the proxy and the output about 12 times. The multiplier of 3 above is too low; try 8 until more runs are measured. No price is entered, so no money figure is shown. Console model runs now allow 150 calls.

Where the numbers come from

  • Per scan, measured with the built-in agents: Auditor 2,016 in and 406 out; Investigator 934 in and 131 out; Fixer and Validator 1,777 in and 207 out. The Auditor runs once per scan. The other two run once per finding, so findings per scan scales them.
  • Token counts are a proxy (characters divided by four), not the model's own count. Run python evals/measure_handoffs.py --count-tokens with an endpoint for real counts.
  • The multiplier of 3 is an assumption for context re-reads, retries and guardrail overhead. The first real run (above) measured about 8 on input and 12 on output, so treat 3 as a lower bound.
  • Not included: the person's review time, prompt caching or batch discounts, and larger repositories than the golden projects (one to three files). The rules scan costs no tokens.
