The scan ran to completion (cap not hit): 81 of 150 allowed calls, 28 of 50 steps, 1,143 s of 2,400 s allowed. Previous proxy estimate vs actual

The earlier estimate used characters-divided-by-four as a proxy. The live run shows the proxy significantly underestimates real usage:

Proxy estimate (per finding)Actual (per finding)Ratio
Input tokens~2,950~19,0206.4× higher
Output tokens~338~4,62813.7× higher

Use the actual per-finding numbers above for production cost planning. The multiplier of 3 previously recommended is far too low — use 7–14 depending on finding type.

What is not included

  • The person's review time (Anshu reviewed 7 proposals in the console; actual time not measured).
  • Prompt caching or batch API discounts.
  • Larger repositories — this run covered 28 files. Token counts grow with file and context size.
  • The rules scan itself costs no tokens (it is a plain code tool).
