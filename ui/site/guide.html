How the Security Analyzer works

It scans a Python project for weak spots, proposes a fix for each, tests the fix in a temporary copy, then waits for you to approve, edit or reject it. It never changes your files.

What it does

Finds

SQL injection, command injection and path traversal. It also reports hard-coded secrets, weak password hashes and unpinned packages, but never fixes those.

Proposes and tests

Each fix is applied to a temporary copy, the project's own tests run, and the rules run again. A fix counts as verified only if both pass.

Asks you

Every fix waits for a person. Approved fixes are written to fixes.patch. You apply them yourself.

How it works

A scan is seven fixed steps, run by the orchestrator (plain code, not an agent):

  1. Check the rules file.
  2. Fingerprint your files and make a temporary copy.
  3. The Auditor scans the whole project and ranks the findings.
  4. For each finding, the Investigator traces the cause, and the Fixer and Validator writes and tests a patch.
  5. You decide on each fix.
  6. The orchestrator checks that your original files are unchanged.
  7. It writes the log and the report.

Three rules hold the design together:

  • Each agent can use only its own tools.
  • A fix is called verified by the orchestrator from test results, never by an agent's opinion.
  • Anything the agent is unsure about goes to a person.

More: the canvas is the original design, and the roster explains why there are three agents and one plain-code orchestrator.

How to run it

You need Python 3.11 or newer and one package: pip install jsonschema. A live scan needs the console running on your own machine or a server. The published site on GitHub Pages is read-only: it cannot scan or call a model.

  1. Start the console. Run python ui/server.py and open http://127.0.0.1:8765.
  2. Give it your code. Drop your project folder or a .zip on the left (it should include its tests), or choose Use the demo project (13 findings across six rule types, plus safe files that must produce nothing).
  3. Connect a model (optional). Choose a provider, paste your key, press Connect, then Test. Without one, the built-in agents run, need no key and send nothing anywhere.
  4. Press Run scan. Watch each agent work. For every ready fix press Approve this fix or reject it, enter your name and press Finish.
  5. Take the result. The report, the decision log and fixes.patch are on the run's page. Nothing is applied to your files; you apply fixes.patch.

If you leave the page while a scan runs, come back to the console and it reconnects to the scan.

python ui/server.py                                   # the console
python -m orchestrator.cli run <folder> golden/rules.json   # the same scan from a terminal
python -m unittest discover -s tests                  # the tests
python evals/run_evals.py                             # score the 21 test cases
python kill_checks.py --run                           # the eight kill switches

Safety. To check a fix, the project's own tests run on the machine that hosts the console. Host it only where that is acceptable, scan only code you trust, and put it behind a token if anyone else can reach it. Hosting notes.

Connect a model

  1. In the console's Model panel choose OpenAI (GPT), Anthropic (Claude) or Google (Gemini), pick or type a model name and paste your API key. The request format follows from the provider. Or put AI_MODEL_ENDPOINT, AI_MODEL_NAME and a key (OPENAI_API_KEY, ANTHROPIC_API_KEY or GEMINI_API_KEY) in a .env file and press Use .env.
  2. Press Test. It sends one tiny message with no project data.
  3. By default all three agents use the model. You can leave any of them on the built-in version.
  4. Run a scan. The header shows the AI calls and tokens used.

Secrets and personal data are masked before anything is sent. The model never receives a path, rules file or test command that the harness did not give it. Use fake or non-sensitive code until your security team has approved the provider.

Where it stands

Other results

  • The live run: 10 findings, 7 fixed and approved, 3 left to a person (a redesign, a secret and a dependency, which are never auto-fixed). One command-injection fix needed a retry. Your originals were unchanged. It used 81 AI calls and 236,478 tokens, about $0.75, in about 19 minutes. No limit was hit and no kill switch fired. See the cost page.
  • Red team: 2 of 10 attacks were stopped and 8 broke the system. None of the 8 is fixed yet. They are listed on the test cases page.
  • Kill switches: all eight checks pass.
  • Tests: all 173 pass.
  • Models: GPT-5 has run live to completion. Claude has run through a local bridge. The Gemini adapter has only been tested against a mock server.
