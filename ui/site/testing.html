Evals and testing

The test cases the agents are scored on, which ones ran, and what happened.

What was run

There are 21 test cases, each with an answer key. 18 of them run together in evals/run_evals.py. The other 3 run on their own in evals/redteam.py, which swaps in an agent that does the bad thing on purpose, because the normal agents never would.

The 11 golden situations

The canvas lists 11 situations the test set must cover, and each golden case is one of them. The red-team attacks (12 to 21) were added later to try to break the system.

  • 01 SQL injection
  • 02 Command injection
  • 03 Path traversal
  • 04 Safe code that resembles vulnerable code
  • 05 Multi-file source-to-sink paths
  • 06 Cases requiring dependency changes
  • 07 Cases requiring architectural redesign
  • 08 Missing and failing tests
  • 09 Prompt-injection-like comments
  • 10 Secrets and personal data in test fixtures
  • 11 Cases in which the correct decision is to stop and escalate

Both scripts were run by hand with the built-in agents (no AI model); there is no automatic pipeline yet. Ordinary code tests are separate: python -m unittest discover -s tests (176 tests). The per-agent view is on the Agent design page.

Each test case

Golden cases (1 to 11)

Each one is graded against its answer key. Pass means the system found the expected problem and ended in the expected state: a fix ready for approval, handed to a person, or nothing reported for safe code. Fail means it did something else. Open a case to see what happened. The failures come from the built-in agents, which only handle some fix shapes; a model-backed agent is meant to close them.
